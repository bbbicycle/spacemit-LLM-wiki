# 查询范围与证据升级

默认选择能回答问题的最小资料，不机械遍历知识层级。

| 意图 | 默认入口 | 需要继续核实的情况 |
| :--- | :--- | :--- |
| 选型、对比、产品定位 | `search_wiki` 定位后读相关正文 | 摘要缺少关键指标、代际或测试条件 |
| 方案、原理、可行性 | `read_knowledge_atom` | 专题未覆盖问题、口径冲突或已过期 |
| 电气、引脚、寄存器 | `get_evidence_fact` | 适用板型或版本不明、缺少关键接线条件 |
| 驱动、构建与底层调试 | 相关专题或事实表；不足时查原始文件 | 需要定位源码、复核命令或补充日志 |

任何层级均可因证据缺失、冲突、过期，或用户要求核实上游而升级。先 `search_raw_sources` 定位文件，再 `read_raw_source_file` 读取相关范围。用户未提供报错堆栈不构成禁止查原文的理由。

## 范围读取

- 原文请求默认返回 200 行，显式范围最多 500 行；有明确问题时按 `has_more` 和 `next_start_line` 续读。优先读取章节或匹配附近的内容。
- 不把整个 `Sources/`、完整图谱 JSON 或所有命中正文送入上下文。不在 Sources 根目录执行无边界递归搜索；限定子模块、路径、文件类型及结果数量。
- 复用已读取且版本适用的证据。普通问答以 1～3 次调用为目标，不为凑满预算而查询，也不因超出预算而省略必要核实。
- 工具服务进程加载索引或为切片下载源文件，不等于 Agent 收到全量正文；需要控制的是工具返回大小和进入上下文的内容。

## 停止条件

核心结论有证据、关键条件已明确、下一次查询不会解决实质缺口时即可停止。正文与摘要冲突时以核实后的原始证据解释差异，不擅自消除冲突。仍无法确认时说明资料缺口和可确认范围。

## MCP 异常或缺少 Sources

1. 优先在本地精炼层 `Developer_Journeys/`、`Knowledge_Atoms/`、`Evidence/` 定向查找。
2. 需要上游证据时，优先沿用原始目录清单的路径；访问 `spacemit-com` 官方 GitHub 仓库的同源公开内容。
3. 缺少 Sources 不应清空已有原始目录索引。网络和官方路径不可达时明确报告，不猜测内容。

## 回答

先给结论和适用条件，再给必要数据及出处。保留待审核、撤回、冲突与过期提示。类比只在有助理解时使用，不额外增加无关芯片细节。
