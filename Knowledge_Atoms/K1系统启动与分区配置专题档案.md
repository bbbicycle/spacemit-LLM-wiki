# K1 系统启动与分区配置专题档案

> [!TIP]
> **💡 工程师导读与排坑焦点**：详解 Ramfs 调试启动、自启脚本、U-Boot 与 OpenSBI 固件合并及隐藏分区。
> **目标读者**：`BSP 工程师 / 系统移植` | **技术领域**：`bsp_kernel_drivers`

本专题档案详细记录了 K1 芯片的系统启动流程控制、固件合并生成（U-Boot + OpenSBI）以及板级 GPT 分区的高级配置。

---

## 1. 系统启动深度定制

### 1.1 使用指定 ramfs 快速启动
在开发调试阶段，可以使用 PC 端的 `fastboot` 配合 U-Boot 命令行，无需烧录即可加载指定的 ramfs 进行系统验证：
1. **PC 端推送镜像**：
   ```bash
   fastboot stage vmlinuz-6.6.36
   fastboot stage k1-x_FusionOne.dtb
   fastboot stage rootfs.cpio.gz
   ```
2. **U-Boot 端映射地址并引导**（地址及大小可根据实际微调，底层参数参见 [[Evidence/k1_hardware_debug_parameters]]）：
   ```c
   fastboot -l 0x20000000 0
   fastboot -l 0x30000000 0
   fastboot -l 0x32000000 0
   bootm 0x20000000 0x32000000:0x1251000 0x30000000
   ```

### 1.2 修改默认加载的 dtb 方案
K1 启动时默认从板载 EEPROM 读取 `product_name` 来自动选择匹配的 dtb 设备树。
*   **无 EEPROM 场景**：若板卡未贴 EEPROM，或者需要强制指定默认 dtb，可在 U-Boot 头文件 `uboot/include/configs/k1-x.h` 中修改默认宏：
    ```c
    #define DEFAULT_PRODUCT_NAME "k1-x_deb1"
    ```
    重新编译部署后，系统在未读取到 EEPROM 时将默认使用该宏定义的 dtb。

### 1.3 自定义开机自启脚本
添加开机脚本的方法取决于目标文件系统的类型：
*   **基于 Bianbu OS**：
    在 `/etc/init.d/` 目录下创建脚本（例如 `S50_testscript`），通过文件名开头的数字决定上电启动的先后顺序。必须使用 `chmod a+x /etc/init.d/S50_testscript` 赋予执行权限。
*   **基于 Bianbu Minimal**：
    直接在根目录下创建或编辑 `/etc/rc.local` 写入自定义命令，并执行 `chmod a+x /etc/rc.local` 确保其在开机时被加载。

### 1.4 长按 Power 键触发自定义行为
在产品设计中，常需要通过长按电源键执行关机或启动自定义脚本（如 `power_off.sh`）。
1.  **按键消抖策略**：
    为避免机械抖动，需修改内核驱动 `drivers/input/misc/spacemit-pwrkey.c`，利用软件延时过滤高频抖动：
    ```c
    // 记录按下与释放的 cycles
    cycles_t fall_cycle;
    cycles_t rise_cycle;
    
    // 在 pwrkey_fall_irq 中判定间隔
    fall_cycle = get_cycles();
    if (fall_cycle - rise_cycle > 150000) {
        input_report_key(pwr, KEY_POWER, 1);
        input_sync(pwr);
        fall_triggered = 1;
    }
    ```
2.  **长按检测脚本 (Shell 方案)**：
    利用 `evtest` 后台监控 `/dev/input/event0` 节点，当检测到按键按下（`value 1`）累计达到设定阈值（如 30 次，约 3 秒）且未释放时，执行目标脚本：
    ```bash
    evtest /dev/input/event0 > /root/tmp_event_info.txt &
    # 在循环中判断 count_num 并清空临时事件文件
    ```
3.  **系统级按键屏蔽**：
    若使用自定义按键服务，需在 `/etc/systemd/logind.conf` 中屏蔽系统默认的按键响应，防止冲突：
    ```text
    HandlePowerKey=ignore
    HandlePowerKeyLongPress=ignore
    ```

## 2. 固件合并与隐藏分区配置

### 2.1 将 U-Boot 与 OpenSBI 合并为单一 itb
为了简化烧录固件的分区管理，可将 U-Boot 和 OpenSBI 编译合并为一个 FIT Image（`.itb`）：
1. **取消 U-Boot 原有分区限制**：在 U-Boot `menuconfig` 中取消选中 *"Second partition to use to load U-Boot from"*，将分区名改为 `opensbi-uboot`。
2. **编写 ITS 描述文件**：创建 `uboot-opensbi.its`，在 `images` 节点下同时声明 `uboot`、`opensbi` 和目标板 `fdt` 的加载地址（如 U-Boot 的 `load = <0x0 0x00200000>`），在 `configurations` 节点中将 `firmware` 设为 `opensbi`，`loadables` 设为 `uboot`。
3. **生成 ITB 镜像**：
   ```bash
   mkimage -f uboot-opensbi.its -r u-boot-opensbi.itb
   ```
4. **修改 GPT 分区表**：修改 `partition_universal.json`，删除原 `uboot` 分区，将 `opensbi` 分区更名为 `opensbi-uboot`，大小调整为两者之和（如 3MB），并烧录该 `.itb`。

### 2.2 配置隐藏分区
为了保护系统底层的关键数据（如 `bootinfo`、`fsbl`、`env`）免受最终用户或外部应用意外读写，可以在分区表配置文件 `partition_universal.json` 中配置 `"hidden": true` 属性：
```json
{
  "name": "fsbl",
  "hidden": true,
  "offset": "128K",
  "size": "256K",
  "image": "factory/FSBL.bin"
}
```
配置为隐藏的分区在 GPT 分区列表中将默认不予显示，提供了额外的系统安全保障。

### 2.3 U-Boot 阶段通过 DTS 预启电源轨
某些关键外设（如板载以太网 Switch 芯片）要求在 U-Boot 甚至 SPL 阶段就必须上电。此时可通过修改 PMIC 伴随电源的设备树引脚配置来实现：
*   **编辑设备树** `arch/riscv/dts/k1-x_spm8821.dtsi`，在目标电源轨节点下添加 `regulator-boot-on` 属性：
    ```c
    // 以使能外设 Switch 供电为例
    sw_2: SWITCH_REG1 {
        regulator-boot-on;             // 开机时自动开启电源
        regulator-name = "switch1";
        regulator-state-mem {
            regulator-off-in-suspend;  // 在 suspend 状态下关闭电源
        };
    };
    ```
    重新编译部署 U-Boot 后，系统将在引导的最早期自动开启该路供电。
