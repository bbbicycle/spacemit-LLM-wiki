# K3 芯片开发快速上手向导

先明确 K3 的板型、内存容量、系统镜像和 SDK 版本。30B-A3B 是 MoE 示例，总参数与激活参数分别记录，不能据激活量推定完整权重占用。

## 1. 认识芯片与板卡边界

[K3 产品简介](../Sources/docs-chip/zh/key_stone/k3/k3_docs/root_overview.md) 列出 8 个 X100 计算核与 8 个 A100 智算核，支持 RVA23 Profile；K1 的 X60/RVA22 不能套用。SoC 能力、板卡引出接口和运行时支持分开核对；60 TOPS 不能直接换算成任何模型的生成速度。

## 2. 核对供电勘误与散热

K3 指南 V1.1 的 1.2.5/1.2.6 与 [硬件设计 Buglist](../Sources/docs-chip/zh/key_stone/k3/k3_hw/k3_hw_design_buglist.md) 要求合并相关核心电源，并处理 VDD0V8_DDR 供电平面的专项勘误；读 [[Knowledge_Atoms/SpacemiT生态板卡与PMIC电源配合专题档案]]，不能复制旧独立供电方案。散热参考 [[Knowledge_Atoms/K3热设计与散热专题档案]] 和 [[Evidence/k3_thermal_specs]]：历史 θJC/PL1/PL2 缺少条件时不能作为已核验设计输入。

## 3. 配置启动与烧录

读 [[Knowledge_Atoms/K3启动模式与Strap管脚配置专题档案]] 与 [[Evidence/k3_strap_pins_config]]。保留指南 1.1.5 的管脚清单矛盾，按功能表与板型原理图核对；例如 GPIO66/65 的 0/0 是 TF Card → eMMC 顺序。不能从默认电平直接给出未核实的电阻/悬空接线。

## 4. 选择系统路径

[K3 SDK 概览](../Sources/docs-chip/zh/key_stone/k3/k3_sw/k3_sdk_user_guide.md) 区分 Buildroot、Bianbu、OpenHarmony 与 AI Robot。选择对应分支和板型镜像，再按该 SDK 编译/烧录；SDK 概览本身不支持用一条通用 `make` 命令构建所有系统。

## 5. 运行并测量大模型

读 [[Knowledge_Atoms/K3大模型本地推理与AI算力专题档案]] 与 [[Evidence/k3_ai_performance_data]]。当前 [Llama.cpp 指南](../Sources/docs-ai/zh/compute_stack/ai_compute_stack/llama.cpp.md) 的 Bianbu 路径安装 `llama.cpp-tools-spacemit`，以 Qwen3-30B-A3B-Instruct-2507-Q4_0 为例：

```bash
llama-bench -m Qwen3-30B-A3B-Instruct-2507-Q4_0.gguf -t 8 -p 64 -n 64 -mmp 0 -fa 1
```

模型需先按指南下载并确认内存足够；命令和参数绑定对应运行时版本。分别记录提示处理、生成速度、内存和上下文，不能把 FP8 硬件支持等同于所有框架已支持，也不能将单次实测推广为性能保证。
